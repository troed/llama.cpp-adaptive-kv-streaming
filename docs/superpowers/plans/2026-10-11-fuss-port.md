## Global Constraints

- Base is exactly `upstream/feature/adaptive-kv-stream-v2` = `1240f34c7`. Do **not** refresh ggml-org master in this effort.
- Working branch is `fuss`. Work happens in the **main workspace** (`/home/troed/llama.cpp-adaptive-kv-streaming`), never a worktree: the host actions build only `build/`, `build-tests/`, `build-tests-cuda/` there.
- Port only the 20 commits listed in Tasks 1–7. The 16 dropped commits (section 5.1 of the spec) are not replayed.
- Single source of truth for the streamed span ceiling: `GGML_KV_STREAM_SPAN_QUERY_WIDTH`, value **8**, defined in `ggml/src/ggml-kv-stream-partial.h`. Do not reintroduce it anywhere else, and never leave a second numeric copy of the ceiling.
- MTP draft ceiling: `LLAMA_KV_STREAM_MTP_DRAFT_MAX`, value **5**.
- Sizing rule: an owner that answers `alloc_size` asserts it will not hand the op to stock attention; the CUDA gate additionally floors any non-`streamed` answer at the stock figure (`std::max`), so it can never size below stock.
- No feature ships without passing the improvement gate (Task 8) — a neutral or negative result means drop it, not keep it.
- Build/test evidence is only valid from the host actions; the sandbox has no `nvcc`.
- Detached builds: read the marker count BEFORE launching, then wait with
  `sh .superpowers/sdd/2026-10-01-streamed-sizing-contract/wait-build.sh <count> <log>`; the marker is `BUILD_EXIT=` / `TESTS_BUILD_EXIT=` / `TESTS_CUDA_BUILD_EXIT=`.

## Review Focus

1. **A wide (5–8 query) op the stream model claims but actually serves through `ops->direct`** rather than as span tiles: its `tileable` promise is creation-time only, so a run-time `direct` path can under-reserve and 500 the decode. Expected: the gate never hands such an op a figure smaller than what the run-time path needs.
2. **`q->ne[1]` of 5–8 with `ncols2 == 8`** gives `ncols = 64`, which may exceed the stock `ggml_cuda_fattn_mma_get_*` tables: expected is a clean plan rejection and fallback to stock attention (a TG dip), never a mis-sized launch or a crash.
3. **Draft depth 5 with an ngram-only drafter (no MTP attached):** the MTP cap must not clamp the ngram drafter's own `n_max`. Expected: ngram-only decoding is unchanged from the unported tip.
4. **Isolating one feature for the gate may not compile** because the features share expression sites (the gate, `mma_span_launch_make`, the speculator): expected is that an isolation variant is a deliberate stub, recorded as such, not a silent partial build.
5. **A long run with graph rebuilds** (the bounded CUDA-graph cache): the bound could evict a graph mid-stream and cost TG. Expected: VRAM plateaus and TG does not regress versus unbounded within measurement noise.
